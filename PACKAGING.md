## Prototype verification

Build-MousePrototype.ps1 requires the stock SHA-256 documented in SPIKE.md.
It requires a new output path and leaves the input file untouched. A 100%
build emits a byte-identical stock copy. A 50% build was inspected with
Iced using the two hook RVAs from NativeTrace.md and the new section at
0x002C3000. The two axis accumulators are separate. Runtime and Steam
launch compatibility remain unverified.

## Runtime test status

Direct launch was attempted from an isolated copy of the clean backup.
In the sandbox, both executables failed with Illegal System DLL
Relocation. Outside the sandbox, both the stock executable and the
50% prototype exited with code 1 before a game window appeared. This
test does not establish whether the prototype runs through Steam.

## Steam-assisted launch

Stock Steam app 4834790 opened a responding Theocracy window. With Steam
running and app ID 4834790 declared in the isolated copy, both the stock
build and the hash-verified 50% build opened a responding game window.
Each isolated process was stopped after the startup check. This confirms
that the 50% executable loads. It does not measure pointer movement.
steam_appid.txt was created only in the isolated test copy and is not a
mod package file.

The integrated patch modifies only the main executable. It reads the
existing Help and Credits layout at runtime. A title-screen left click
is tested using the game's software cursor, and the matching down/up
events are consumed when Options handles the click. The patched
executable, stock backup, installed.sha256, Options.ini, and isolated
test copy's steam_appid.txt are local files and should be left out of
the distribution.

The Options dialog also saves SkipOpeningVideos=0 or 1 in Options.ini.
The executable patch checks it synchronously at startup and bypasses
the logo and intro movie batch when enabled. The main-menu Intro command
has its own playback call and remains available. The checkbox defaults
to off. The startup branch was checked in disassembly.

## Windows signing requirement

The isolated build failed with Bad Image status 0xc0e90002. Windows
Code Integrity events 3077 and 3033 identify TheocracyOptions.dll as
blocked by the active signing policy. The DLL is unsigned x86, matching
the game's architecture. A test environment that allows this build, or
code signing accepted by the active policy, is needed for live testing.

## Native title menu

The current build registers Options with the game's own title-menu button
constructor. The entry uses the stock menu font and is positioned between
Help and Credits using their game coordinates. A menu command opens the
settings dialog. The earlier Windows button overlay is superseded.

The isolated copy reached the main menu with opening videos disabled.
Options was verified visually between Help and Credits. The UI automation
click produced a Windows cursor at the target without moving Theocracy's
software cursor, so physical-click verification is still pending.

## Mod UI convention

Use the game's existing UI containers, controls, fonts, and input routing
for new screens. The stock Exit confirmation is the reference for native
dialogs. Avoid Windows overlays, which do not receive Theocracy's software
cursor. Preserve the spacing and left alignment of stock menu entries.

The Options panel now uses the stock Exit panel constructor, registration
and close path. It uses native buttons for 5% increments, an on/off row
for opening videos, and Apply and Cancel. Help, Options, Credits and Intro
are separate rows at the stock 30-unit spacing.

## Shared Game Settings

The title-screen Options command now opens the stock Game Settings panel.
The panel constructor attaches Mouse Speed and Skip Opening Videos from
both the title-screen and in-game entry points. Mouse Speed reuses the
stock slider widget, art and input handling. The original Scroll Speed
control owns border scrolling. The earlier mod-specific scroll multiplier
and its executable hooks were removed. The old MouseBorderScrollSpeed
INI value is no longer read. Stock scroll settings stay in .gamesettings,
which the game writes through its normal settings flow.

The shipped modification still patches only the stock executable and
adds the mod DLL. The installer and source are distributed in the mod
folder. Do not package player settings from either .gamesettings or
Options.ini.

Mouse Speed is placed directly below the stock Scroll Speed control and
uses the game's localized Low / High labels. Skip Opening Videos uses
the same two-state gem control and art as CD Tracks.

## Province mouse-wheel zoom

The executable patch redirects the province world draw at RVA 0xFA687,
the five province-local pointer conversions at RVAs 0xFA772, 0xFA7A7,
0xFA851, 0xFA881 and 0xFA8AD, and the DirectInput mouse event switch at
RVA 0x1663A7. Regenerate the executable together with the matching DLL.
The zoom release introduces no additional packaged assets.

Normal View starts at the stock camera distance. Each wheel notch changes
distance by five percentage points. Wheel up moves closer, capped at 70%.
Wheel down moves farther, capped at 150%. The view is centered in the
current province rectangle. The DLL restores the stock 16-bit surface
before the HUD draws and converts viewport clicks using the last drawn
world sample. Other camera modes use their stock renderer.

The isolated build loaded, and the player confirmed both scroll directions
zoomed the world while the HUD stayed fixed in Normal View. Unit picking,
box selection and orders still need live verification at the zoom caps.

The zoom compositor uses pixel-center filtering to reduce shimmer during
panning. It limits blending to source pixel edges when zoomed in and
uses bilinear sampling when zoomed out. At 100% the game still draws the
world directly. The filter update only requires a DLL replacement for
installations that already have the zoom executable patch.

The zoom filter reuses the horizontally filtered results for adjacent
output lines. This is a DLL-only optimization and leaves the filter
output and camera timing unchanged.

## Control-group camera focus

Ship the rebuilt Options DLL and matching executable builder. The
builder changes only the stock main executable, redirecting the battle
camera call at RVA 0xFAA64 and the group recall call at RVA 0xD7F23.
The builder relocates its mod import tables to make room for the new
exports. Double-tap the same top-row group digit within 350 ms to recall
and focus the commander, or the first live member. Ctrl+number still
assigns the group. No game assets or new settings files are required.
